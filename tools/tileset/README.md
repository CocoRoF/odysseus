# 사무실 타일셋 생성기

`atlas.png` 와 `atlas.ts`(좌표표)를 만든다. 산출물은 `apps/web/public/office/` 와
`apps/web/components/office/` 에 들어가고 **저장소에 커밋된다** — 빌드 때 만들지 않는다.
그래야 `git clone` 한 사람이 바로 띄울 수 있고, 아트가 조용히 바뀌는 일도 없다.

```bash
node tools/tileset/build.mjs
```

## 사람 (images/charactor_NN)

여덟 장(`idle|move` × `down|left|right|up`, 128×128)을 `characters-import.mjs` 가 한 시트로 들인다. 시트는 **월드의 2.5배**
(칸 120px — 원본 키 ~110px 을 거의 그대로)로 짓고, 화면은 월드 크기(48px)로 그리며 `background-size` 로 맞춘다.
예전에는 48px 로 줄여 담아(0.43배) 확대하면 뭉개졌다. 자르는 규칙은 여덟 장의 합집합 상자 하나(원작자의 발 위치 보존),
칸 안에서는 **발 가운데**를 칸 가운데에, 발을 덜 내린 프레임은 바닥까지 내린다(좌표 보정). 매니페스트(`lib/people.ts`)의
`personSpriteStyle()` 이 칸·배율·위치를 한 번에 만든다 — 시트 좌표를 손으로 계산하는 곳이 없다.
`node --test tools/tileset/` 가 여덟 칸 전부에 사람이 있고 발이 바닥에 닿고 발 가운데가 맞는지 시트 픽셀로 검사한다.

## 그림의 출처

소품·바닥·벽은 `images/office_pixel_assets_128` 팩, 사람은 `images/charactor_NN/` 의 128px 도트 여덟 장, 팩에 없는
엘리베이터 문만 `draw2.mjs` 가 2배로 그린다. 예전에 32px 붓으로 그리던 소품(draw.mjs)은 팩 옆에 서면 거칠어
전부 뺐다 — 화면에 있는 모든 그림이 같은 해상도(월드의 2배 이상)다.

## 구입한 팩 Office-3 (images/Office-3) — 소품·벽의 정본

RPG Maker 규격이다: **한 칸 48px**. `tile-B-01~05.png`(768×768, 16×16칸)가 물건 시트, `Auto-tile-A4-walls-2/3.png`(768×720)가
벽 오토타일이다. `office3.mjs` 가 시트의 **모든 물건(472개)** 을 칸 사각형(cx, cy, w, h)으로 안다 — 붙어 있는 물건(책상 줄·캐비닛
더미·복사기 짝·주방 조리대)은 자동 분할이 합쳐 버리므로 사람이 경계를 적었고(`tools/tileset` 의 세그먼트·격자 크롭으로 하나씩
확인), ㄱ자 물건은 `cells` 로 칸을 나열한다. 매니페스트가 발자국(`foot` — 아래에서 몇 줄이 바닥을 차지하는가, 나머지는 위로
솟는다), 벽걸이(`wall`), 밟는 것(`walk`), 한국어 라벨, 팔레트 묶음(`group`)을 정한다. 의자 색은 그림에서 잰다.

`pack-import.importOffice3` 가 칸 그대로 잘라 내고(다듬지 않는다 — 칸이 곧 발자국 단위), `build.mjs` 가 **묶음마다 한 장**의
시트(`atlas-<묶음>.<해시>.png`, 폭 16칸)로 낸다. 전체를 한 장에 넣으면 4MB 라(촘촘한 픽셀 아트) 층이 쓰는 묶음만 받도록 나눴다.
배율은 **1**(48px = 월드 한 칸) — 픽셀 아트를 다시 샘플링하지 않고 화면이 `image-rendering: pixelated` 로 늘린다. PNG 는 Paeth
필터로 쓴다(20% 작다). 좌표표(atlas.ts)는 `ATLAS`(묶음 시트)·`S`(sheet 포함)·`FOOT`·`PROP_META`(라벨·묶음)·
`LEGACY_PROP_NAMES`(옛 팩 이름 → 새 이름, 저장된 프리셋 이전용)를 낸다.

바닥은 팩에 없다 — 이전 팩(`images/office_pixel_assets_128`)의 열한 장과 참고 그림의 회색 바닥(images/office_room_ref, `room-ref.mjs`
슬라이서)을 그대로 쓴다. 128px 그림이 2×2칸(월드 96px)이다.

### 벽 — A4 오토타일

블록 하나(96×240)가 벽 한 가지다: 위 2×3(96×144)이 **윗면**(RPG Maker A2 형식: 맨 위 왼쪽 칸에 안쪽 모서리 넷, 그 오른쪽은
미리보기, 아래 2×2 가 가장자리·가운데의 4×4 4분면), 아래 2×2(96×96)가 **앞면**(4×4 4분면). 칸 하나는 24px 4분면 넷으로 그리고,
어느 4분면을 쓸지는 이웃에 달렸다 — 윗면은 8방향(대각선이 비면 안쪽 모서리), 앞면은 좌·상·우·하. 256가지 8방향 마스크는
**47가지 그림**으로 줄어든다. `pack-import.importA4Walls` 가 `office3.mjs` 의 `WALL_STYLES`(사무실에 어울리는 열다섯 가지)마다
47 + 16 장을 한 줄 16칸 시트(`wall-<스타일>.<해시>.png`, 768×192)로 미리 그려 두고, 좌표표는 마스크 → 칸 번호 표
(`WALL_TOP_VARIANT[256]`, `WALL_FACE_VARIANT[16]`)를 낸다. 화면은 칸마다 div 하나로 그 칸을 background-position 으로 고른다.

## 고품질 텍스처로 바꿔 끼우기

그린 그림은 출발점이다. **더 좋은 PNG 가 있으면 파일만 두면 된다** — 코드는 건드리지 않는다.

```
assets/office/sprites/<이름>.png     ← 소품·벽걸이 하나 (예: vendingTall.png, highTable.png)
assets/office/tiles/carpet.png       ← 바닥 (128×128 로 반복), hall.png 도 같다
assets/office/tiles/wall-h.png       ← 벽 (32×32 로 반복), wall-v.png 도 같다
```

- 크기는 **무엇이든 된다** — 32·64·128·256 … 표준 크기 어느 것이든. 빌드가 그 스프라이트의
  칸 크기(아래 표)로 면적 평균 축소해 넣는다. 원본이 클수록 결과가 곱다.
- 투명 배경(PNG 알파)이어야 한다. 바닥에 닿는 부분은 아래에, 키가 큰 것(자판기 2칸)은 위로 솟는다.
- 이름과 칸 크기 표는 `assets/office/SPRITES.md` 에 있다 — `node tools/tileset/build.mjs` 가 만든다.
- 다시 `node tools/tileset/build.mjs` 를 돌리면 끝. 산출물은 커밋한다.

## 장면 (서서 이야기하는 사무실)

이 사무실에는 앉기가 없다. 방 하나에 장면 하나 — `apps/web/components/office/scenes.ts` 가 아홉 장면
(휴게실·화이트보드 앞·커피 코너·라운지·복합기 코너·게시판 앞·회의실·스탠딩 데스크·서버실 앞)의
**방 크기(cols×rows)·모양(cuts — 도려낸 모서리)·바닥·소품 배치·사람이 서는 자리와 보는 방향**을 정한다.
방마다 크기와 모양이 다르고(ㄱ자·ㄷ자), 장면은 시험의 분야에서 고르되 층 안에서 겹치지 않게 나눈다.
같은 장면이 한 층에 두 번 서면 두 번째는 좌우를 뒤집는다. 새 장면을 더하려면 그 파일에 한 항목을 더한다 —
`floorplan.test.ts` 가 소품 겹침·문에서의 도달·시작 지점 앞 칸·벽걸이 자리·벽 덮임을 남/북 × 거울 전부에 대해 검사한다.

관리자는 `/admin/office` 에서 같은 모양의 장면을 직접 만들 수 있다(타일·에셋·NPC 자리·시작 지점·문). 저장된 장면은 DB(`office_presets`)에
있고, 시험이나 분야 기본값으로 연결된다 — `docs/DEVELOPMENT.md` 의 "사무실 커스텀" 참조.

## 방 참고 그림 → 바닥 (images/assembled_preview_on_gray_floor.png)

`node tools/tileset/room-ref.mjs <그림> images/office_room_ref` 가 빈 방 그림을 열아홉 조각으로 자르고 원본으로 다시 조립해
대조한다(0.15% 어긋남, `room-ref.test.mjs`). 지금 화면이 쓰는 것은 그 바닥 타일(floor-slate·hall·carpet)뿐이다 — 벽은 Office-3.

## 벽·복도

RPG Maker 식이다. 방 둘레 **한 칸(48px)** 이 벽 **윗면**(검은 천장 + 밝은 테두리)이고 옆방과 나눠 쓴다. 위 벽의 **앞면**(남쪽에서
보이는 벽면)은 그 아래 한 줄을 더 차지한다 — 방은 위 고리 아래 한 줄(방 상자 = 고리 + 앞면 + 안쪽 rows + 고리 = rows+3 줄),
복도는 북쪽 방 문 벽 아래 한 줄(복도 = 앞면 + 걷는 세 줄). 벽걸이는 그 앞면에 걸린다(키 큰 것은 윗면 줄까지 솟는다).
문 통로는 고리 칸 + 그 너머 앞면 칸(두 칸 높이)이고 방 바닥이 이어진다. 도려낸 칸(컷)은 윗면이되 바로 아래가 바닥이면
앞면이 된다(두꺼운 벽의 남쪽 면). 벽은 손으로 놓지 않는다 — 층 전체를 한 격자에서 분류하고(`floorplan.floorWalls`) 8방향
이웃으로 변형을 고르므로 방 사이·복도 벽의 테두리가 저절로 이어진다. 벽 스타일은 장면이 고른다(`SceneSpec.wall`, 기본
베이지) — 나눠 쓰는 칸은 먼저 차지한 방의 것, 복도 앞면은 그 위 칸의 것. 편집기(RoomView)는 방 혼자 분류한다.

화면은 **발끝 y 로 깊이를 정하는 한 층**에 가로벽·벽걸이·소품·책상·사람을 함께 그린다 — 소파 뒤에 선 사람은
소파가 가리고, 방에 들어서면 문 벽이 다리를 가리고, 복도에 서면 그 벽 앞에 선다.

복도에는 왼쪽 끝 엘리베이터(출근 자리), 문마다 출입 매트, 방이 없는 가장자리를 막는 벽과 그 벽의 벽걸이, 양 끝 화분이 있다.

## 규칙

1. 빛은 **화면 위에서 하나만** 온다. 북쪽 모서리에 밝은 선, 남쪽에 어두운 앞면.
2. 바닥은 **밝다.** 어두운 페이지 위에 밝은 층이 놓여야 무대처럼 읽힌다.
   (이전 구현이 실패한 가장 큰 이유가 바닥까지 어두웠던 것이다.)
3. 색은 면당 3단계 + 접지 그림자. 검은 외곽선은 긋지 않는다.
4. 팔레트는 `palette.mjs` 한 곳에서만 온다.
5. 난수를 쓰지 않는다 — 같은 입력이 같은 픽셀을 낸다.

# 캐릭터 프리셋 넣기

사람은 여기서 그리지 않는다. **원화를 `images/` 에 넣으면 들여온다.**

```
images/charactor_03/        ← 폴더 하나가 프리셋 하나 (이름은 charactor_NN 또는 character_NN)
  idle-down.png             ← 정면, 서 있는 자세
  move-down.png             ← 정면, 내딛는 자세
  idle-left.png  move-left.png    ← 왼쪽
  idle-right.png move-right.png   ← 오른쪽
  idle-up.png    move-up.png      ← 뒤 (등이 보인다)
  portrait.png              ← 대화창에 뜨는 초상 (세로로 긴 그림)
```

방향은 `down/left/right/up` 대신 `s/w/e/n`, `front/back`, `정면/좌/우/뒤` 도 받는다.
자세는 `idle/move` 대신 `stand/walk`, `정지/이동` 도 받는다.

**두 자세를 주면 걸을 때 번갈아 쓴다.** 한 방향에 한 장만 주면(`s.png` 처럼) 그 한 장을
두 프레임에 같이 써서, 움직여도 자세가 그대로다.

잠시 빼 두고 싶은 프리셋은 폴더 이름 앞에 `_` 를 붙인다 (`_charactor_02`). 지우지 않아도
된다.

```bash
node tools/tileset/characters-import.mjs
```

- 방향 그림은 **정사각**, 초상은 **세로로 길게**(세로/가로 > 1.3) 두면 알아서 구분한다.
- 배경은 투명(알파)이어야 한다. 여백은 자동으로 잘라 내고 키를 48px 로 맞추므로,
  원본 크기는 제각각이어도 게임 안에서는 모두 같은 키로 선다.
- 한 방향의 두 자세는 **키를 함께** 맞춘다. 프레임마다 따로 늘리면 걸을 때 사람이
  아래위로 튄다.
- 파일 이름은 `front/left/right/back`, `정면/좌/우/뒤` 도 받는다. 이름을 못 알아보면
  정렬 순서로 추측하고 **경고를 출력한다** — 그 추측은 믿을 수 없다. 실제로
  charactor_01 은 `정면·좌·우·뒤` 순인데 charactor_02 는 `정면·좌·뒤·우` 순이었다.
- 이름을 붙이고 싶으면 폴더에 `preset.json` 을 둔다:
  `{ "name": "정장 여성" }`

산출물(`apps/web/public/office/people.png`, `portraits/*.png`,
`apps/web/components/office/people.ts`)은 커밋한다. 원본은 `images/` 에 남는다 —
앱은 줄인 것만 받는다.

## 미설정 시

참여자에게 프리셋을 지정하지 않으면 **인물 키에서 하나를 고른다**(`components/office/avatar.ts`).
무작위이되 같은 인물은 언제나 같은 사람이다 — 다시 그릴 때마다 얼굴이 바뀌면
그건 무작위가 아니라 고장이다.
