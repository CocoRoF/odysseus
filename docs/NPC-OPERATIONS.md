# NPC 대화 시스템 — 구현 및 운영

## 사용자에게 보이는 흐름

1. 가까운 NPC를 클릭하거나 Space를 누르면 초상화와 게임 대사창이 열린다.
2. 첫 만남에는 시나리오의 `encounter`를 NPC가 먼저 말한다. 서버가 한 번만 기록하며 LLM이나 자동 사용자 인사는 호출하지 않는다. 이전 만남이 있으면 마지막 NPC 대사를 이어 보여 준다.
3. 대사창 **하단 말걸기**를 누르면 입력란이 열린다. Enter 전송, Shift+Enter 줄바꿈, 한글 조합 입력을 지원한다. 전송하면 입력란을 접고 같은 초상화 대사창에서 답변을 보여 준다. Esc는 입력 접기, 다시 Esc는 대화 닫기다.
4. 머리 위 말풍선은 NPC 간 대화에만 쓴다. 공개 시나리오 상황과 일상 주제를 섞어 2–4개의 짧은 대사를 번갈아 말한다. 관찰 중인 방 하나에서 가까운 쌍을 선택하며 복도에서도 보인다.
5. 사용자 대화 중에는 자동 대화를 일시정지한다. 이미 생성 중인 결과는 보관하고, 대기 작업은 호출하지 않는다. 말한 위치·남은 읽기 시간을 보존해 대화창을 닫고 사용자 응답 작업이 끝나면 재개한다. 탭 비활성화도 일시정지하며, 실제로 상대가 떨어졌거나 접근 권한이 사라진 경우 취소한다.

공통 보행 속도는 52 → 67.6 px/s(1.3배)다.

## 모든 NPC에 공통으로 적용되는 공개 경계

시나리오 스튜디오에서 다음 데이터를 작성한다. 인물이나 문제 ID별 실행 분기는 없다.

| 설정 | 의미 |
|---|---|
| 사무실 첫 대사 (`encounter`) | 대사창에서 먼저 보여 주는 고정된 공개 대사 |
| 공개 배경·사실 | 시나리오의 공개 상황, 활동, 분위기, 겉으로 드러난 긴장 |
| 대화 주제 | `scenario` / `daily`, 대화 목적과 근거 사실 ID |
| 사무실 말투 | 공개 표현 방식 |
| 인물별 대화 참여 상한 | 기본 12회, 0–50회. 사용자별 누적 NPC 간 대화 참여 횟수 |

한 교환에서 같은 NPC가 두 번 말해도 참여는 한 번으로 센다. 실제 말하기 전 취소, 재시도, 일시정지는 횟수를 늘리지 않는다. 새로고침과 공개 설정 변경으로 횟수가 초기화되지 않는다. 사용자와 나누는 대화에는 이 상한을 적용하지 않는다.

AI 공개 설정 작성에는 시나리오 제목·공개 첫 인사말·이름·직함·입력한 공개 배경만 전달한다. `knowledge`, `persona`, 시험 시작 메시지, 문제 파일, 정답·평가 기준은 전달하지 않는다. 제목도 구체 조건을 그대로 옮기는 대신 공개 활동·분위기로 추상화한다. 편집 화면에서는 초안으로 반환해 검토 후 공개한다.

서로 다른 시나리오 출신 NPC도 **발행된 공개 자료**를 바탕으로 이야기할 수 있다. 사실·주제 ID는 출처 시나리오로 구분하므로 같은 ID의 다른 사실이 섞이지 않는다. 두 종류의 주제가 모두 있으면 시나리오 대화 두 번에 일상 대화 한 번을 배정한다. 같은 주제의 반복 사용과 실제 이전 발언도 참고한다.

실행 시 worker는 `OfficeProjection`만 읽는다. 생성 결과를 발화자·길이·출처 ID로 검사하고 별도 모델로 의미와 정보 경계를 검사한다. 시나리오 주제를 일상 잡담으로 대체하거나 숨은 조건·해법을 추론하는 것도 검증 대상이다. 의미 검증은 확률적이므로 모든 표현의 정보 유출 방지를 보장하는 보안 경계로 단독 사용하지 않는다. 비공개 문제 데이터 자체를 런타임 입력에서 제외하는 것이 기본 경계다.

## 기억과 일시정지

세계는 `(사용자, 방/시험, 공개 revision)`별로 저장한다. 새 공개 revision에서도 같은 사용자·같은 방·같은 NPC의 기존 대화와 관계를 찾아 이어간다. 기존 기록을 복사하거나 삭제하지 않는다. 다른 사용자의 세계나 같은 이름뿐인 다른 인물은 합치지 않는다.

- `office_events`: 실제 말한 원문과 상태 전이. 자동 삭제하지 않는다.
- `office_memories`: 출처 ID와 참여자가 있는 기억. NPC 간 생성에는 개인 대화를 넣지 않는다.
- `office_conversations.state`: 자동 대사의 재생 위치, 일시정지 전 상태, 남은 읽기 시간. 미발화 초안은 공개 이벤트·기억이 아니다.
- `office_jobs`: PostgreSQL 큐, 우선순위, 실행 임대, 재시도 세대, 사용량.

자동 대화는 참여자가 들었던 최근 대화와 선택한 주제의 과거 발언을 시간순으로 읽고, 인물별 누적 참여 횟수도 전달한다. 장기 기억은 참여 범위를 먼저 제한한 후 관련도·시간순으로 검색한다. 사용자 대화에는 같은 인물과의 최근 12개 메시지와 관련 기억을 넣는다. 모든 원문을 매 호출마다 전송하지 않는다. 입력 예산이 넘으면 오래된 회상부터 줄인다.

시험에는 만남·인사 여부와 출처 메타데이터만 전달한다. 사무실 대화 원문이나 NPC 간 대화는 문제 응답·채점 입력으로 전달하지 않는다.

## 비용과 운영

API는 메시지와 작업을 함께 저장하고 202를 반환한다. `office-worker`는 LLM 호출 중 DB 연결을 점유하지 않는다. 사용자 작업이 자동 대화보다 우선하며, 중복 요청 ID는 같은 작업을 돌려준다. 실패 재시도는 사용자 메시지를 추가하지 않는다.

현재 기본 채팅 공급자를 모든 사무실 호출과 공개 설정 작성에 사용한다. Anthropic 어댑터는 지원하지 않는 sampling 인자를 전달하지 않는다. OpenAI 호환 자체 서버(vLLM·Ollama·LM Studio·사용자 지정)에는 system 을 `developer`가 아닌 `system` 역할로 보낸다 — system 을 user 메시지에 합치지 않는다. 이미 진행 중인 시험의 고정된 공급자 설정은 별도다.

| 환경 변수 | 기본값 |
|---|---:|
| `OFFICE_WORKER_CONCURRENCY` / `OFFICE_PROVIDER_CONCURRENCY` | 4 / 3 |
| `OFFICE_LLM_TIMEOUT_S` / `OFFICE_JOB_TIMEOUT_S` | 25 / 90초 |
| `OFFICE_AMBIENT_INTERVAL_S` | 60초 |
| `OFFICE_MAX_JOBS_PER_USER_HOUR` / `OFFICE_MAX_JOBS_GLOBAL_HOUR` | 120 / 3000 |
| `OFFICE_MAX_TOKENS_GLOBAL_HOUR` | 8,000,000 |
| `OFFICE_INPUT_CHARS` / `OFFICE_MEMORY_LIMIT` | 14,000 / 8 |
| `OFFICE_CACHE_ENABLED` / `OFFICE_CACHE_MIN` / `OFFICE_CACHE_PER_KEY` / `OFFICE_CACHE_MAX_REPLAYS` | true / 3 / 8 / 40 |

### 잡담 대본 캐시

같은 시험의 사무실은 사용자마다 따로지만, **두 인물이 그 세계에서 처음 나누는 잡담**은 입력이 공개 설정뿐이다(사용자·기억·이전 발화·시각 없음). 이런 대본만 검수를 통과하면 `office_dialogue_cache`에 남기고, 다른 사용자의 세계에서 **같은 짝이 처음 잡담할 때만** 다시 쓴다. 이미 이야기를 나눈 짝에게는 쓰지 않는다 — 첫 만남 대본을 틀면 기억에 없는 만남이 생긴다. 주제는 평소 고르기(시나리오 2 : 일상 1, 덜 다룬 주제 먼저)를 그대로 따른다.

- 키는 발화자 → 수신자, 주제, 공개 지문(두 인물의 공개 설정·장면 공개 자료·정책 판)이다. 공개 설정이 바뀌면 옛 대본은 쓰지 않고 새 대본이 들어올 때 지운다.
- 맞는 대본이 `OFFICE_CACHE_MIN` 미만이면 새로 만든다. `OFFICE_CACHE_PER_KEY`만큼 모이기 전에는 번갈아 새로 만들어 종류를 넓히고, 다 모이면 캐시로 튼다. 한 대본은 `OFFICE_CACHE_MAX_REPLAYS`번까지만 튼다.
- 재생은 공급자를 부르지 않아 공급자 장애·호출 예산과 무관하다. 재생도 평소처럼 실제로 말한 줄만 사건·기억이 되고, 같은 세계에서 같은 대본을 두 번 틀지 않는다.
- 의미 검증은 확률적이다. 잘못 통과한 대본은 여러 세계에 퍼질 수 있으므로 `GET /office/admin/dialogue-cache`(많이 튼 순)로 보고 `DELETE /office/admin/dialogue-cache/{id}` 또는 `DELETE /office/admin/dialogue-cache`로 지운다. 이미 말한 줄은 그 세계의 기록이라 지우지 않는다.

생성 1회와 의미 검증 1회가 기본이다. 형식/근거가 잘못된 생성은 최대 1회 다시 시도한다. 사용자 초안 600, 자동 대화 950, 검증 180 토큰을 제한한다. 공급자 한도 오류는 반복 호출을 차단한다.

## 배포와 공개 설정 작성

```bash
sudo ./scripts/deploy.sh --yes api web
# API 선택 시 office-worker도 함께 배포. 백업·기동·기존 데이터 보존 검사 포함.
```

기존 공개 설정이 비어 있는 시나리오만 일괄 작성하려면 API 환경에서:

```bash
python scripts/author-office-contexts.py prepare /protected/office-drafts.json
# 작성 실패가 있는 경우 완료한 초안은 유지하고 실패한 항목만 보완
python scripts/author-office-contexts.py resume /protected/office-drafts.json
# 파일의 공개 내용 검토 후, 준비 이후 변경되지 않은 행에만 적용
python scripts/author-office-contexts.py apply /protected/office-drafts.json
```

도구는 기존 공개 설정을 덮어쓰지 않는다. 적용 전 상태를 별도 JSON으로 보관하며 시나리오의 비공개 지식·과제 파일·응시 스냅샷을 수정하지 않는다. `/office/admin/metrics`로 원문 없이 작업 상태·공급자·지연을 확인한다.

## 검증 범위

이번 변경의 PostgreSQL 통합 검사는 NPC의 첫 대사·중복 열기·일시정지 전후 재개·생성 중 개입·참여 상한·다음 대화의 과거 발언·공개 revision 변경 후 기억·개인 대화 격리·시험 관계 전달을 포함한다. 프런트 검사에서는 NPC 간 말풍선만 표시하는지 확인한다.

실제 브라우저와 로컬 API·DB·worker에서는 초상화/고정 첫 대사/하단 입력/답변/한글 조합/모바일 배치를 확인했다. 실제 공급자를 사용하는 운영 검증 결과는 배포 PR에 기록한다.
